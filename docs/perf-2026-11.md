# فحص البطء (24 نوفمبر 2026) — مؤجّل، بنرجعله

القياس على قاعدة البيانات الحقيقية (167 حركة ستوك بس، بعد يومين تجربة) وكموظف فرع ومصنع وأدمن.

## الأسباب (بالترتيب)

1. **RLS بتنحسب لكل سطر (80% من البطء، وبيكبر مع البيانات).**
   `private.can_see_location(col)` و`private.is_active_staff()` و`private.can_read_all()` بالـ policies
   (42 policy) بتنعاد مع كل سطر (security definer ما بتنعمل inline)، تقريباً 0.6–0.8 ملي ثانية للسطر.
   مثال: `select count(*) from stock_movements` = 131ms لموظف الفرع و51ms للأدمن على 167 سطر.
   - **الحل:** دالة بترجّع مصفوفة المواقع المسموحة مرة وحدة، والـ policy تصير
     `location_id = any ((select private.visible_location_ids()))`، و`(select private.is_active_staff())`
     و`(select private.can_read_all())` بأقواس select (initPlan، مرة لكل استعلام).
     بالسحابة `alter policy ... using (...)` بدل drop/create (الحذف بيطلب موافقة ما بتوصل).

2. **`v_below_min` = 2–3 ثواني (وصل 7).** الـ LATERAL على `v_factory_batches` بينحسب لكل صنف
   (26 مرة)، وكل مرة بيمر على حركات المصنع مع RLS. مستعمل بالرئيسية (فرع، مصنع، تغليف)،
   والنظرة العامة، والقائمة الجانبية للأدمن.
   - **الحل:** ستوك الدفعات المش منتهية بينحسب مرة وحدة (CTE مجمّع حسب الموقع والصنف) وبعدين join.

3. **القائمة الجانبية للأدمن** (`ActiveNavItems` ← `navCountsAction` ← `attention()` ← `loadOverviewData`):
   مع كل تنقّل بتحمّل كل النظرة العامة (15 استعلام منهم `v_below_min` كامل) بس مشان الأعداد،
   والـ server actions بتصطف وراها (الحفظ بيستنى).
   - **الحل:** دالة أعداد خفيفة لحالها (أو cache قصير)، مش كل `loadOverviewData`.

4. **أصغر:** `report_locations`/`report_products` لـ 30 يوم 0.2–0.4 ثانية (نفس سبب 1).
   Vercel المجاني بينام: أول فتحة بعد توقف +1–2 ثانية.

## مش هم السبب
- المكان: Vercel `fra1` وSupabase `eu-central-1` (فرانكفورت الثنين).
- حجم JS عالجوال طبيعي (~420KB مضغوط لكل التطبيق، وexceljs وAnthropic مش بالمتصفح).
- الصفحات بتستعمل `Promise.all` (مش استعلامات ورا بعض).
- الكرون (`call_reminders`) 23ms بالمتوسط، وبـ service role (بدون RLS).
- الفهارس الناقصة على المفاتيح الأجنبية (65 من الـ advisor) مش مؤثرة هلا بهالحجم.

## طريقة القياس
`pg_stat_statements` بالسحابة، و`explain analyze` كدور `authenticated` مع `request.jwt.claims` لموظف
حقيقي، وجدول مؤقت بيقيس كل استعلام لكل دور (فرع، مصنع، أدمن). بعد الإصلاح: نفس القياس قبل/بعد،
وكل فحوصات pgTAP (خصوصاً RLS: الفرع ما بيشوف غير موقعه).
